## What this is
The **Representative Location Explorer** — a research decision-support web app that selects
and explains 20 representative U.S. locations (5 climate regions × 4 urbanicity classes)
for national building-stock and heat-health simulations. Born from a PhD project; turned
into a deployed app.

- **Live demo (synthetic data):** https://representative-location-explorer.onrender.com
- **Repo:** https://github.com/hampochimacyril/Location-representation-explorer (branch `main`)
- **Version:** 1.1.0 · Method version 2.0

## Architecture & file map
- `backend/data_service.py` — read-only ingestion of analytical CSVs + ZIP crosswalk;
  **dual data mode** (real outputs vs bundled `data/demo/`); ZIP resolution; dashboard.
- `backend/scoring.py` — deterministic scoring + **min-cost flow** distinct-location
  allocation; `evaluate()` returns selections, changes, and summary metrics.
- `backend/models.py` — `ScenarioConfig`/`Override` validation (weights must sum to 1.0).
- `backend/service.py` — lazy, fault-tolerant service accessor + `/api/health` payload.
- `backend/server.py` — zero-dependency stdlib HTTP server (local). Security headers.
- `backend/fastapi_app.py` — managed FastAPI app (deploy target; `$PORT`). Security headers.
- `frontend/` — dependency-free SPA: `index.html`, `styles.css`, `app.js` (6 pages:
  overview, ZIP explorer, scenario builder, ranking, allocation, methodology).
- `data/demo/` — synthetic dataset (generated by `scripts/generate_demo_data.py`).
- `data/zip_crosswalk_demo.csv` — small HUD-USPS-compatible ZIP crosswalk subset.
- `scripts/` — `generate_demo_data.py`, `refresh_data.py` (manifest + SHA-256), `run_dev.py`.
- `tests/` — `test_scoring.py`, `test_api.py`, `test_project_contract.py`, `e2e/` (Playwright).
- `marketing/` — `promo.html` (narrated, voice picker), `promo.mp4`, `VO_script.md`,
  `generate_promo_video.py`. Build artifacts under `marketing/_*` are gitignored.
- `render.yaml`, `Procfile`, `Dockerfile`, `.github/workflows/ci.yml` — deploy + CI.

## Data modes (important)
Resolution order in `data_service._resolve_analysis_dir()`:
1. `RLE_ANALYSIS_DATA_DIR` env var (used verbatim — fails loudly if wrong);
2. real processed outputs at `../../location_selection/data/processed/` if present;
3. bundled `data/demo/` (public demo, CI, reviewers).
`/api/health` and the UI report `data_mode` (`production`|`demo`). The public deploy is
demo-only; the private analytical outputs are never published.

## Invariants — do NOT break (tests enforce these)
- Exactly **20 strata**, one selection each; **20 distinct** catchments when the unique
  constraint is on.
- Rural → `catchment_type=County`, filter `in.county`; non-rural → `CBSA`, filter
  `in.metropolitan_and_micropolitan_statistical_area`. Never substitute `in.city`.
- Selection is **deterministic** (same inputs → same outputs).
- Score weights must sum to 1.0 (`models.py` raises otherwise — a test asserts this).
- Leading-zero geographic identifiers are preserved as strings.
- The default Philadelphia (CBSA 37980) research-priority override sits at unconstrained
  rank 2 in Mixed-Humid HDU.
- Front-end strings asserted by Playwright/contract tests must be preserved (page labels,
  KPI labels, button names, "2,959 candidates", etc.).

## Run / test / deploy
```bash
python3 -m backend.server                 # local, http://127.0.0.1:8787 (demo fallback)
python3 -m unittest discover -s tests -v   # full suite (runs on demo data)
node --check frontend/app.js               # front-end syntax
python3 scripts/generate_demo_data.py      # regenerate demo data
uvicorn backend.fastapi_app:app --port 8787  # managed path (Render uses $PORT)
```
CI (`.github/workflows/ci.yml`) runs unit + smoke + e2e on every push to `main`.

## Conventions
- Keep the front end dependency-free (no build step, no framework, no browser storage).
- Additive changes preferred; preserve method/test invariants above.
- New scenario alternatives stay `REVIEW REQUIRED` until ResStock enumeration is verified.
